THE CORE IDEA
Death is the progression mechanic. A run is expected to end in dying,
and that is not a failure — it is the point. Every run earns shards,
and shards buy permanent unlocks in the hub between runs. Each unlock
makes the next run go deeper. The whole game is built around that loop:
delve, die, bank, upgrade, delve further. A run that reaches its end on
a fresh character is not supposed to be possible. The satisfying
feeling is stacking enough upgrades over many runs that the dungeon
finally gives way. Anything that erodes the loop — too much shard
income, rewards that skip tiers of grinding, deaths that stop happening
— breaks the game's central idea.

PROJECT
Mobile-first touch dungeon crawler. Single HTML page, no build step,
no libraries. Plain scripts under one global namespace: Delve.
Hosted on GitHub Pages. Save key: underward_save_v3.
Everything is authored and managed from Termux on Android.

WARD STRUCTURE
Each ward is 10 floors. The 10th floor of each ward is its own boss
arena — nothing else on that floor. Bosses fall on floors 10, 20, 30,
40, and so on, one per ward.

Every ward brings its own palette, its own monster roster, its own
special-floor behaviour, and its own boss with a distinct theme and
sprite. Loot rarity and enemy difficulty both scale with depth.

Total planned: around 10 wards / 100 floors. What exists so far, and
what is written but not yet built, is recorded in architecture.md.
